# Web 9ボール ビリヤードゲーム

## Problem Frame

Webブラウザ上で本格的に遊べる9ボールビリヤードゲームを、学習目的で開発する。Three.jsを使った3D描画と物理シミュレーションを自作し、AIと対戦できる完結したゲームを完成させる。対象ユーザーは開発者本人（学習・技術習得）。

## ゲームフロー概要

```
ゲーム開始
    │
    ▼
ラック配置（1〜9番ボール、ひし形）
    │
    ▼
┌── プレイヤーターン ──────────────────┐
│  ドラッグ＆リリースでショット         │
│  ↓                                    │
│  物理シミュレーション中（入力ロック）  │
│  ↓                                    │
│  結果判定                             │
│   ├─ ポケット成功 → 継続 or 勝利確認  │
│   └─ ファウル → ファウル通知 →        │
│             AIターン（相手がBIH）      │
└───────────────────────────────────────┘
    │
    ▼
┌── AIターン ─────────────────────────┐
│  「AIが考え中」演出                   │
│  ターゲットボールを計算               │
│  ショット実行                         │
│  物理シミュレーション中（入力ロック）  │
│  結果判定                             │
└───────────────────────────────────────┘
    │
    ▼
いずれかが9番をポケット → 勝敗表示 → リスタート
```

## Requirements

**9ボールのゲームルール**
- R1. ボール構成は手玉（キューボール）1個＋1〜9番ボール9個の計10個
- R2. ショット時は必ず手玉が最小番号のボールに最初に当たらなければならない
- R3. 有効なショット（R2に従い手玉が最小番号ボールに最初に当たること）で9番ボールをポケットに入れたプレイヤーが即座に勝利する。ファウルショットで9番ボールが入った場合は勝利とならずR4のリスポットルールを適用する
- R4. ファウル条件：手玉のポケット、最小番号以外への先当たり、ボール未接触。ファウル発生時は相手がボール・イン・ハンドを得る。ファウル中に入った番号ボールはそのまま残存する。ただしファウルショットで9番ボールが入った場合のみ、9番ボールをテーブル中央にリスポットする

**ゲームフロー**
- R5. ゲーム開始時に9個のボールをひし形ラック配置で並べる。1番ボールを先頭（頂点）、9番ボールを中央に固定し、残りの2〜8番ボールは残り7ポジションにランダムに配置する。
- R6. プレイヤーとAIのターンが交互に進行する
- R7. いずれかが勝利した際に勝敗画面を表示する（テーブルはその背後に残存）。プレイヤー勝利とAI勝利で別のメッセージを表示し、リスタートボタン（新しいラックから再開）を提供する

**プレイヤー操作**
- R8. ドラッグ＆リリースでショット：手玉からドラッグした方向の逆方向へ、距離に応じた強さで手玉を打つ。最小ドラッグ距離（例：10px相当）未満の解放はショットとして扱わない（誤タップ防止）
- R9. ショット準備中（ドラッグ中）にプレイヤーのエイムライン（手玉の直線予測軌道）を表示する。クッション反射は表示しない。最初に当たるオブジェクト（ボールまたはクッション）で終端する
- R10. プレイヤーがボール・イン・ハンド（相手のファウル後に手玉を任意位置に配置できる権利）を得た際、テーブル上のクリックした位置に手玉を配置できる。配置位置はテーブル境界内かつ既存ボールと重複しない位置に限る。配置確定後にドラッグでショットを開始する

**ゲーム状態管理**
- R11. 物理シミュレーション実行中（ボールが動いている間）はプレイヤー入力を受け付けない。全ボールが一定速度以下（実装時に調整）で停止したらターン操作を再開する
- R12. ファウル発生時に画面にファウル種別（例：「ファウル - 先当たり違反」）とボール・イン・ハンドの旨を通知表示する
- R13. 常時HUDを表示する：現在のターン（プレイヤー / AI）、現在のターゲットボール番号（テーブル上に残る最小番号）

**3Dビジュアル**
- R14. Three.jsで3Dビリヤードテーブルを描画し、カメラは斜め上の固定視点とする
- R15. ボールは3D球体で表現し、ライティングと光沢素材を適用してリアルな質感を出す
- R16. テーブルは緑のフェルト素材、木製のクッション（レール）を表現する
- R17. ポケットは4隅と両長辺中央の計6か所に配置する

**AI**
- R18. AIターン開始時に短い「AI思考中」演出（例：0.5〜1秒の待機表示）を行ってからショットを実行する
- R19. AIは常にルール上有効な手（手玉が最小番号ボールに最初に当たるショット）を選択する。直接ラインが取れない場合はバンクショット（クッション経由）を試みる。それも不可能な場合はファウルを受け入れる（ゲームは継続する）
- R20. AIの狙いにランダムな角度誤差を加えて非完璧に振る舞う。ただし誤差はターゲットボールに到達できる範囲に収め、永久にターゲットに当たらない状態を回避する

## Success Criteria

- 9ボールのルール通りにゲームが最初から最後まで進行し、勝敗が正しく判定される
- AIが毎ターン有効なショットを行い（またはファウルを受け入れて）、ゲームが必ず終了する
- ボールの衝突・反射が不自然に見えない（激しいすり抜けや爆発がない）
- Three.jsによる3D表示でビリヤードらしいビジュアルになっている
- プレイヤーは常に自分のターン・ターゲットボール・ファウル有無を画面から把握できる

## Scope Boundaries

- オンライン対戦・マルチプレイは対象外
- スコア保存・ランキング機能は対象外
- AI難易度の複数段階選択は対象外（まず1段階）
- モバイル・タッチ操作の最適化は対象外（PCブラウザ向け）
- スヌーカー・8ボールなど他のゲーム種別は対象外
- エイムラインのクッション反射表示は対象外
- カメラ操作（ズーム・パン）は対象外（固定視点のみ）
- ショット中のパワーゲージ表示は対象外（ドラッグ距離で直感的に判断）

## Key Decisions

- **Three.js（3D描画）+ 2D物理のハイブリッド**: ビリヤードの物理は本質的に2D平面上の運動であるため、3D物理エンジンは使わず、2D上の弾性衝突計算をThree.jsの3D表示に投影するアプローチを採用する。Three.jsの学習と物理の学習を両立しつつ、完成可能な難易度に抑える。なお既存2D物理ライブラリ（Matter.js、Planck.jsなど）についても計画時に評価し、自作 vs ライブラリ使用を決定する（特にトンネリング問題への対処のため）。
- **ドラッグ＆リリース操作**: 最もシンプルで直感的な操作方式。モバイル不要の前提のためマウス操作に特化する。
- **2D-3D座標マッピング**: 物理計算（2D x-z平面）とThree.js描画（3D）の完全なマッピングコントラクト（原点位置・軸方向・単位比）を計画段階の最初に確定する。エイムライン・ポケット判定・ボール配置が全てこれに依存するため、実装の起点となる。
- **ファウル判定：リアルタイム衝突イベント記録**: 物理シミュレーションの毎ステップで手玉が他のボールに接触した際、そのボールIDをタイムスタンプ付き衝突ログに追記する。ファウル判定はショット終了後にログの先頭エントリ（最初に接触したボール）を参照して行う。

## Dependencies / Assumptions

- Three.js（CDN or npm）を使用する。バージョンはr150以上の最新安定版を推奨（光沢素材APIの安定性のため）
- PCブラウザ（Chrome / Firefox / Edge）での動作を前提とする
- ビルドツールは軽量なもの（Viteなど）を想定するが、実装時に決定
